▶ How to Use This Page — Step-by-Step Click to view step-by-step instructions

Recommended approach: use the Data Solution Architecture Questionnaire to drive this page automatically.

  1. Fill in the Data Solution Architecture Questionnaire — tick patterns, add context, and run the sync script. It will populate Sections 9–14 of this page and regenerate all diagrams automatically.
    python confluence_sync_questionnaire_to_main.py
  2. Or fill this page directly — follow this sequence:
    • Sections 1–2 (Solution Overview + Introduction): front-sheet for governance, plain-English description, business outcomes, strategic alignment
    • Sections 3–4 (Background + Pain Points): as-is architecture snapshot and current pain points — drives the “why we’re changing” narrative
    • Sections 5–6 (Functional + Non-Functional Requirements): what the solution must do and at what performance/security levels
    • Section 7 (HLD Options): 2–3 architectural options with pros/cons and evaluation criteria — needed for governance gate
    • Section 8 (Pattern Selection — 8a to 8f): select approved UKHSA patterns for ingestion, processing, storage, integration, governance/security, infrastructure (INF), and target state (TSA). INF-01 and INF-05 are always mandatory.
    • Section 9 (Context Entities): external actors, systems, and partners — drives the Context View diagram
    • Section 10 (Architecture Components): every component with its layer, technology, and cloud — drives the Solution Architecture and Logical View diagrams
    • Section 11 (Architecture Connections): source → destination flows with protocol and auth — drives all connection diagrams
    • Section 12 (Network Segmentation): VPC/subnet CIDRs, connectivity type, security group rules — drives the Network Segregation diagram
    • Section 13 (Data Flows): numbered flows with sensitivity, format, and frequency
    • Section 14 (Dataset Inventory): named datasets and relationships — drives the Dataset Relationship diagram
  3. Run diagram generation after Sections 9–14 are populated:
    python confluence_update_diagrams.py
    This generates: Solution Architecture, Data Flow, Dataset Relationship, Context View, Logical View, Authentication Flow, and Network Segregation diagrams.
  4. Complete Sections 15–16 (LLD Summary + Cost Comparison) after HLD options are agreed at governance review.
  5. Complete Sections 17–19 (Implementation Handover, Cost Comparison, Roadmaps) before handing over to the delivery team.
  6. Generate the implementation pack (Terraform scaffolds + delivery summary):
    python confluence_generate_implementation_pack.py

⚠ Do not edit the Architecture Diagrams child page or the LLD page directly. They are fully generated from this page — any manual edits will be overwritten on the next run.
